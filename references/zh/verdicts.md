# 裁决——把负责人的回答折回去，以及线什么时候可以改

## 折回
1. 在每个受影响的线文件末尾追加 `## 裁决（<日期>，<人>）`；保留问题编号让出处可追。每条裁决一个
   要点，结尾写对新代码的含义（「新注册进 `selfLogic.ts`；`loader/` 不是死代码」）。
2. 裁决改变了正文某句话的，正文也改（一行、便于 diff），并引用裁决编号。
3. 升格进索引：已确认的**规则**（每次新改动都要守的）、已确认的**设计**、已确认的**漂移**（别模仿）、
   答「留」的遗留。
4. 更新 `questions.md` 状态：已答 / 未决 / 撤回（撤回 = 代码答了；写清答案是什么）。
5. 记录谁确认的。多人仓库很正常：「不是我定的」是合法裁决。

## 确认对之后任务的意义
- ✅ 已确认的线和规则是权威：新代码照做，不再问。
- 未确认的线可读，但不能单独驱动改动；agent 说明自己在做什么假设并标出来。
- 索引支持的话，把未确认的线标 `hidden`，不进默认上下文；靠引用仍可达。

## 线什么时候可以改（且只有那时）
- 负责人明确改了数据流、归属、汇合点、形状或扩展配方。
- 一条新的底层规则得到确认。
- `check.sh` 报出结构漂移（新汇合点、家族形状挪了）且负责人确认是有意的（否则是要记录的漂移，
  不是新标准）。
普通功能——哪怕加了两个文件——永远不改线。agent 可以在汇报里*提议*改线；不擅自动手。

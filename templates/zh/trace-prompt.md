你在 <仓库路径>（<一行：技术栈、workspace 布局>）。任务：追踪并写出 **<线名>** 这条线——
<一句话：这条线是什么，从哪到哪>。这是给项目负责人确认用的「项目理解」文件，不是给模型的说明。

## 已知机械证据（可直接引用；不必重算）
- <粘贴 mechanical/ 里与本线相关的部分：家族形状计数、汇合点计数与差集、时间轴首尾、配方交集、
  import 方向相关行、churn 首尾>
- 现有文档只作线索、必须对着代码核：<列表>。文档与代码不一致处要明确写出。

## 怎么做
1. 从 <入口文件> 出发，沿 import/调用追到 <终止条件：一个成员被渲染 / 一个事件被执行 / 一次值传播>。
   用 grep/sed/cat 读代码，不要复述文档。
2. 完整读样板成员（<样板 A：奠基>、<样板 B：最近且干净>）+ 另外 2–3 个 + 证据里列出的每个离群成员。
   不要读全部 N 个成员。你声称的数字要数出来。
3. 每条机制性论断引 `file:line`。讲清每个声明字段被谁消费、成员导出什么、谁调它、怎么注册、
   状态住哪、不许碰什么。
4. 把不合形状的分成：**另一类**（不同机制）/ **漂移**（同机制、走歪）/ **其实合规**（文件不同、
   机制一致）。给理由和计数。
5. 算「加一个」：≥3 次成员出生提交的触碰文件取交集；与汇合点代码、与已有清单对照；不一致写出。
6. 待确认：≤5 条，只在「两种解释都通、且答案改变新代码去向」时才问；点名成员/文件；一问一事。
7. 记录你打开了多少个文件。

## 输出
写 `<目标>/lines/<NN-名字>.md`（mkdir -p），**≤300 行**，严格照 `<templates/zh/line.md 路径>`
的模板（同标题、同顺序）。然后只回：≤15 行摘要 + 待确认清单原文 + 打开文件数。不要把文件贴回来。
